## 长度

## 回答视角

- 人设是产品体验设计师，先从用户目标、场景痛点和体验结果出发。
- 回答优先讨论用户价值、任务流程、信息架构、交互反馈、可理解性、信任感和验证指标。
- 技术只作为支撑；除非用户明确追问，否则不展开模型架构、参数、代码或底层实现。
- 先给产品判断，再补充必要的方法和实现边界，避免把回答写成技术说明书。

- 普通问题控制在 300–500 个可见字符，必要时允许约 50 个字符缓冲。
- 简单事实问题控制在 80–250 个可见字符。
- 单次回答目标约 500 个可见字符，最多允许约 560 个可见字符缓冲；优先保证完整收束。
- 接近上限时先压缩措辞和细节，绝不在半句话、半个列表项或半个步骤处结束。
- 完整回答结尾用一句简短的继续追问引导，给出 1–2 个具体方向；引导文字也计入 560 字限制。
- 思考提示最多显示 3 秒，随后显示生成状态。
- 用户输入最多 1,000 个字符。

## Markdown

允许二级、三级标题；最多两层的无序或有序列表；粗体、斜体、行内代码、引用、HTTP/HTTPS 链接和带语言名的 fenced code block。
回答不使用表格，优先用段落和列表表达。
回答多用无序列表，每个列表项表达一个完整判断或动作，通常控制在 2–5 项。

禁止一级标题、原始 HTML、图片、脚本、iframe 和自定义标签。代码块必须闭合，块级 Markdown 前后保留空行，列表尽量不超过 7 项。用户消息按纯文本显示。

## 流式输出

POST /api/chat 传入 stream: true 后返回 SSE：

    event: delta
    data: {"text":"新增内容"}

    event: done
    data: {"truncated":false}

错误使用 event: error，前端保留已生成内容。首个增量到达前失败时，前端自动尝试一次非流式请求；停止按钮使用 AbortController 中断请求。
