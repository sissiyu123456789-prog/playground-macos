# 判断没变，对象变了

入行这些年，我越来越确认一件事：设计这行，从头到尾都是靠“判断”吃饭的。画得快、工具熟，只是把方案端上桌的速度；真正值钱的，是坐下来之后那句“哪个对、哪个不对、为什么”。这句话从来没有变过，变的是判断的对象。

## 一、以前，判断的对象是结果

以前我们判断的是确定的结果：信息层级对不对、用户能不能看懂、流程会不会卡住。判断的对象是已经成形的东西，标准来自经验、审美和对人的理解。那时候判断的密度很低，一周能认真判断三五个方案就不错了，剩下的时间大多耗在“把方案做出来”上。

## 二、现在，判断的对象是过程

大语言模型不是数据库，而是在语料上拟合出的条件概率分布 `P(输出｜输入)`。它不存储答案，只统计“下一个 token 最可能是什么”。模型天生有方差：温度调高是一种说法，调低又是另一种说法。以前判断“哪个结果好”，现在要判断“这个分布有没有被约束到可预期的区间”。判断的对象，从成品移到了过程。

## 三、判断输入怎么被理解

做交易 Agent 时，我搭了一套三级意图体系，用两万条真实 query 打标。表面上这是业务分类，本质上是把产品判断写进模型的输入侧：

- 建立显式 taxonomy，让“烤鸭推荐”和“迪士尼几点关门”在生成前就分流。
- 用 JSON schema 和 reasoning 字段约束模型先讲理由、再下结论，压低幻觉并保留审计线索。
- 把承接策略编码进分类标准，让意图识别可以直接连接后续动作。

以前判断“用户能不能看懂这个结果”，现在判断“模型能不能听懂这句话”。

## 四、判断输出怎么被信任

模型优化的目标是“像”而不是“真”，它没有事实指针，所以会一本正经地编。“可信”因此成了需要设计的东西：

- 通过白盒化溯源披露数据源和工具调用链路。
- 区分权威与非权威来源，允许用户控制检索源。
- 把检索源的选择变成可见、可控的产品机制，约束检索空间。

以前判断“反馈够不够清楚”，现在判断“置信度怎么翻译成信任”。

## 五、判断质量怎么被定义

AIGC 的输出同样服从分布，没法一次画对。我在智能画布里把质量控制从生成端挪到评估端：

- 用 0–10 分梯度评级，把质量差异变成可比较的尺度。
- 用粗规则加细评分，把正样本做成训练信号。
- 用 badcase 反向过滤，再让模型只负责填槽。

以前判断“这张图行不行”，现在判断“这套评估标准能不能兜住这个分布”。

## 结语

AI 没有改变设计师的本质，改变的是判断的位置。以前判断在终点，现在判断在全程：输入怎么被理解、输出怎么被信任、质量怎么被定义。这碗饭还是那碗饭，只是下筷的地方从看得见的地方，挪到了看不见的地方。
